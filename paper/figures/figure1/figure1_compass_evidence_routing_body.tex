% Figure 1 -- COMPASS: provenance-constrained evidence routing.
%
% COMPOSITION.  Wide and shallow, 13.97 x 8.80 cm.  Mechanisms are DEMONSTRATED
% with one worked lineage; every symbol in the drawing is a symbol of the paper
% (Sec. 2.1, 2.2, 3.1, 3.3, App. A).  There is no figure-only notation.
%
% OBJECT GRAMMAR (one glyph = one kind of object).
%  * Programs are cards or table rows: seed p_0, parent s, child p, slot z_i,
%    task t_i = (s_i, P_i).
%  * Instances x_j are chips.  A green chip is a proposal instance (x in P),
%    a blue outlined chip is an admission instance (x in A).
%  * The committed cache is the partial table q_t(u,x) of Sec. 2.1, drawn as
%    programs (rows) x instances (columns).  A cell is observed (light blue),
%    missing (dash), or observed-but-hatched: x lies in the lineage birth set
%    B_u of that ROW, so the observation is stored but never credited to u.
%    Amber frames mark Omega_t(s), the legal evidence of the current candidate.
%  * Amber is the credit chain: Omega_t(s) -> r_sx -> G_s -> routing.
%
% ONE MEANING FOR RED.  Red (with hatching on chips and cells) marks exactly
% one condition everywhere: an instance lies in the birth provenance of the
% lineage in question.  It appears (i) under P in the wave row, since
% P subset X(s,P) can never certify p, (ii) on hatched cache cells, since
% x in B_u is never credited to u, and (iii) on the refused admission batch,
% since x_3 in X(s_m,P_m).  All three are the same rule.
%
% WORKED EXAMPLE (consistent across the whole drawing).
%  * B_s = {x_3, x_4}: the batch that created s from p_0.
%  * This wave proposes on P = {x_1, x_2}: these update row s and are legal
%    for s, but become the birth provenance of p, so (p, x_2) is hatched.
%  * A = {x_5, x_6} is disjoint from X(s,P) = {x_1,...,x_4}; the admitted
%    child p is committed there.
%  * The credit region prints no numbers.  Its three boxes name the objects
%    Omega_t(s) -> r_sx -> G_s; the table shows what they act on.
%
% LIFECYCLE the drawing closes.
%  * The wave row commits the admitted child into the table (top lane).
%  * Row s of the table feeds the credit chain; hatched cells emit nothing.
%  * G_s ranks slots (panel 1) and selects references (panel 2).
%  * Both panels return committed observations via labelled lanes:
%    proposal rollouts commit q_t(z_i, x) for x in P_j into the parent row;
%    an admitted child commits q_t(p_i, x) for x in A_i as a new row.
%  * The credit path ends at the terminal program, the only object that
%    reaches the budget boundary.
%
% EQUATION NUMBERS are typeset literally and must track main.tex:
%   Eq. (1) recursive exclusion X(s,P)      [eq:recursive_exclusion]
%   Eq. (2) routing credit G_s              [eq:global_key]
%   Eq. (4) max-weight proposal assignment  [eq:proposal_assignment]
%   Eq. (5) paired admission gate Delta_i   [eq:admission_gate]
%
% Vertical grid (cm):
%   8.32  wave row
%   7.86  provenance notes under P and A, commit label
%   7.58  commit lane into the cache
%   7.38-5.48  committed cache table (left); three credit steps (right)
%   5.28-4.80  cell legend (left)
%   4.97  routing credit pill (right)
%   4.44  fork to the two workload panels
%   4.26-1.26  workload panels
%   0.98  return lanes
%   0.56  budget boundary, straddled by the terminal program
